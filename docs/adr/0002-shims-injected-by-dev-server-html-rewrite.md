# Shims are injected by the dev server, not through CDP

Every App is served by our local dev server, which rewrites each HTML document so that the Shim bootstrap runs before any App script. It also answers the `$WEBAPIS/webapis/webapis.js` URL itself. We don't use CDP's `Page.addScriptToEvaluateOnNewDocument` or Tauri initialization scripts, because the former doesn't exist on M47 and the latter don't apply to external Engines (ADR-0001). HTML rewriting works the same on every Engine milestone and can be tested without a browser. CDP is reserved for the few things only it can do: trusted key events, the TV screen (viewport size and scaling, the black behind transparent areas, the Engine window's size), screenshots, reload, swapping stylesheets in place on hot reload, console capture, evaluating expressions in the page for the Session handle, reading Shim state the Host needs (Remote Key registrations, ADR-0007), pausing a hidden App (in the debugger, on Engines without page lifecycle states), letting the Engine's own inspector share the Session's connection on Engines that take one debugging client, and closing the Engine. It is never used to inject Shims. The one page script it adds is the backdrop layer behind the page: the transparency checkerboard, a debugging aid the developer turns on and the App never relies on, and, on Engines that can't paint transparent areas black themselves (M47), the TV's black. The backdrop is added once each document has loaded, so on those Engines a page shows the Engine's white until then.

## Consequences

- All injected JavaScript must run on M47, so the Shim bundle is compiled to ES5.
- For Dev Server URL Apps, our server sits in front of the developer's bundler as a proxy so it can rewrite HTML.
